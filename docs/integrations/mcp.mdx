## Overview

Dograh exposes an [MCP (Model Context Protocol)](https://modelcontextprotocol.io/) server that lets AI assistants like Codex, Claude Code, Claude Desktop, Cursor, and the Grok browser connector access your workspace and documentation. Once connected, an assistant can list your agents, fetch agent definitions, and search Dograh docs on your behalf.

## Prerequisites

- Your Dograh MCP endpoint:
  - Self-hosted example: `https://voiceeu.activi.io/api/v1/mcp/`
  - Hosted: `https://app.dograh.com/api/v1/mcp/`
  - Generic: `<YOUR_BACKEND_URL>/api/v1/mcp/`
- Credentials — pick one:
  1. **Browser OAuth (recommended for connectors)** — paste the MCP URL only; the client redirects you to Dograh to log in and approve access (`AUTH_PROVIDER=local`)
  2. **Access token** — short-lived JWT / Stack token in `Authorization: Bearer …`
  3. **API key** — long-lived `dgr_…` key

The endpoint is also shown in **Platform Settings → MCP Server** inside the Dograh UI.

<Note>
If you deployed Dograh to a remote server using [`setup_remote.sh`](/deployment/docker#option-2%3A-remote-server-deployment), your endpoint is served with a self-signed SSL certificate. Claude Code will refuse MCP connections to it unless you start the CLI with TLS verification disabled:

```bash
NODE_TLS_REJECT_UNAUTHORIZED=0 claude
```

This is only required for self-signed certificates. If you have set up a [custom domain](/deployment/custom-domain) with Let's Encrypt certificates via Certbot, no extra flag is needed.
</Note>

## Authentication

### Option A — Browser OAuth (Authorization Code + PKCE)

Supported when `AUTH_PROVIDER=local` (typical self-hosted / OSS deployments).

This is the flow Grok, Cursor, Claude, and other MCP connectors use when you **only paste the MCP URL** and save — no manual API key:

1. The connector POSTs to the MCP endpoint without credentials.
2. Dograh responds **HTTP 401** with  
   `WWW-Authenticate: Bearer FAKESECRET_g3h4i5j6k7l8m9n0o1p2="https://<host>/.well-known/oauth-protected-resource/api/v1/mcp"`.
3. The client discovers the Authorization Server, registers as a public OAuth client (PKCE), and **opens a browser** to  
   `https://<host>/api/v1/oauth/authorize`.
4. You sign in with your Dograh email/password and click **Sign in & Allow**.
5. The client receives an access token and reconnects to MCP automatically.

#### What to enter in the connector

| Field | Value |
|---|---|
| MCP URL | `https://voiceeu.activi.io/api/v1/mcp/` (or your host) |
| Auth | Leave empty / “OAuth” — do **not** put `/auth/login` as the MCP URL |

Status / discovery (for debugging):

```bash
curl -s https://voiceeu.activi.io/api/v1/oauth/status | jq
curl -s https://voiceeu.activi.io/.well-known/oauth-protected-resource/api/v1/mcp | jq
curl -s https://voiceeu.activi.io/.well-known/oauth-authorization-server/api/v1/oauth | jq
```

<Note>
Browser OAuth requires the reverse proxy to route `/.well-known/*` to the **API** (not the UI). Hostinger/Traefik labels in `deploy/hostinger/docker-compose.yaml` include this. Without it, discovery fails and the connector never shows a login page.
</Note>

### Option B — Access token (manual Bearer header)

#### Self-hosted / local auth (`AUTH_PROVIDER=local`)

```bash
curl -s -X POST https://your-dograh-instance/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"your-password"}'
# → { "token": "<jwt>", "user": { ... } }
```

```text
Authorization: Bearer <jwt>
```

#### Hosted / Stack Auth (`AUTH_PROVIDER=stack`)

```text
Authorization: Bearer <stack_access_token>
```

Browser OAuth (Option A) is **not** available when `AUTH_PROVIDER=stack` — use a Stack access token or an API key.

### Option C — API key (legacy / long-lived)

Generate a key at `/api-keys`. See [API Keys](/configurations/api-keys).

```text
X-API-Key: dgr_...
# or:
Authorization: Bearer dgr_...
```

API keys start with `dgr_`. When a Bearer value has that prefix, the MCP server treats it as an API key.

## Grok browser connector

1. Open the Grok agent MCP / connectors settings.
2. Add server URL: `https://voiceeu.activi.io/api/v1/mcp/`  
   (use your own host if different — **must** end with `/api/v1/mcp/`, not `/auth/login`).
3. Save — Grok should open a browser (or embedded window) to Dograh’s OAuth page.
4. Log in with your Dograh account and click **Sign in & Allow**.
5. Return to Grok; the connector should show **Connected**.

If no login appears: check `GET /api/v1/oauth/status` (`enabled: true`) and that `/.well-known/oauth-protected-resource/api/v1/mcp` returns JSON (not an HTML login page).

## Claude Code

### OAuth (local auth deployments)

Paste only the URL; Claude Code will run the OAuth browser flow when the server challenges with 401:

```bash
claude mcp add --transport http dograh https://voiceeu.activi.io/api/v1/mcp/
```

### With an access token or API key

```bash
claude mcp add --transport http dograh https://voiceeu.activi.io/api/v1/mcp/ \
  --header "Authorization: Bearer YOUR_ACCESS_TOKEN"

# or
claude mcp add --transport http dograh https://voiceeu.activi.io/api/v1/mcp/ \
  --header "X-API-Key: YOUR_API_KEY"
```

## Codex

```toml
[mcp_servers.dograh]
url = "https://voiceeu.activi.io/api/v1/mcp/"
# OAuth: omit headers and let Codex run the browser flow (local auth).
# Or set a token/key:
# http_headers = { "Authorization" = "Bearer YOUR_ACCESS_TOKEN" }
# http_headers = { "X-API-Key" = "YOUR_API_KEY" }
```

## Claude Desktop

```json
{
  "mcpServers": {
    "dograh": {
      "url": "https://voiceeu.activi.io/api/v1/mcp/"
    }
  }
}
```

For header-based auth, add a `headers` object with `Authorization` or `X-API-Key`.

## Cursor

`~/.cursor/mcp.json` or project `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "dograh": {
      "url": "https://voiceeu.activi.io/api/v1/mcp/"
    }
  }
}
```

Cursor should open the OAuth login when the server returns 401. If your Cursor build does not support MCP OAuth yet, set headers manually:

```json
{
  "mcpServers": {
    "dograh": {
      "url": "https://voiceeu.activi.io/api/v1/mcp/",
      "headers": {
        "Authorization": "Bearer YOUR_ACCESS_TOKEN"
      }
    }
  }
}
```

## Example prompts

Once the MCP server is connected:

- "List my agents in Dograh."
- "Show me the definition of the agent called *Lead Qualifier*."
- "Search the Dograh docs for how to configure a TURN server."

<Note>
Agent edits are saved as a new **draft** version — your published agent keeps serving calls until you explicitly publish the draft from the Dograh UI.
</Note>

## Migration notes

- **Existing API-key MCP configs keep working** (`X-API-Key` / `Bearer dgr_…`).
- **Browser OAuth is new** for `AUTH_PROVIDER=local` — no permanent key required for connectors.
- Reverse proxy must route `/.well-known` to the API (Hostinger compose ships this).
- Access tokens from OAuth are the same local JWTs as `/api/v1/auth/login` (lifetime: `OSS_JWT_EXPIRY_HOURS`).
- No new required environment variables; OAuth uses `BACKEND_API_ENDPOINT` / `PUBLIC_BASE_URL` for issuer URLs.
