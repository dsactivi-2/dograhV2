## API key authentication

API keys are the recommended way to authenticate long-lived programmatic requests. Pass your key in the `X-API-Key` request header.

```bash
curl https://your-dograh-instance/api/v1/workflow/fetch \
  -H "X-API-Key: dgr_your_api_key"
```

API keys are scoped to an organization. All resources created or accessed using a key belong to that organization. Keys are minted with a `dgr_` prefix.

### Create an API key

Create keys in the dashboard under **Settings → API Keys**. The full key is shown **only once** at creation time — store it immediately in a secrets manager or environment variable.

<Note>
For self-hosted deployments using local auth, sign up and log in via the dashboard first, then create an API key there before making API calls.
</Note>

### Manage API keys

| Action | Method | Path |
|---|---|---|
| List keys | `GET` | `/user/api-keys` |
| Create key | `POST` | `/user/api-keys` |
| Archive key | `DELETE` | `/user/api-keys/{api_key_id}` |
| Reactivate key | `PUT` | `/user/api-keys/{api_key_id}/reactivate` |

Archiving a key immediately revokes it. All subsequent requests using that key return `401`.

## Access token authentication (Bearer)

You can also authenticate with a short-lived access token instead of a permanent API key. Pass it as:

```bash
curl https://your-dograh-instance/api/v1/workflow/fetch \
  -H "Authorization: Bearer <access_token>"
```

| Deployment | How to obtain a token |
|---|---|
| Self-hosted (`AUTH_PROVIDER=local`) | `POST /api/v1/auth/login` or `/auth/signup` — response includes a JWT |
| Hosted (`AUTH_PROVIDER=stack`) | Stack Auth session access token (same token the web app uses) |

This is the preferred path for MCP clients and interactive agents that should not store long-lived API keys. See [MCP Server](/integrations/mcp#authentication).

## Error responses

| Status | Cause |
|---|---|
| `401 Unauthorized` | Missing, invalid, or expired credentials |
| `403 Forbidden` | Valid credentials but insufficient permissions for the resource |

```json
{
  "detail": "Invalid or expired API key"
}
```
